# Skill: Web Design Guidelines Review

Use this skill before demos, launch, or completion of UI work.

## Review Areas

- Purpose: the page has a clear goal and primary action.
- Content: headings, copy, and CTAs match the audience and offer.
- Layout: visual hierarchy guides scanning and does not rely on repetitive blocks.
- Accessibility: keyboard access, labels, contrast, focus states, and semantic structure are covered.
- Responsiveness: mobile, tablet, and desktop layouts are usable.
- Forms: labels, validation, success, error, and spam/abuse expectations are handled.
- Trust: testimonials, proof, policies, location, and contact details are credible where relevant.
- Performance: images, fonts, and scripts are not wasteful.

## Output Format

When files are known, report findings in practical file:path terms. For visual-only review, use a checklist grouped by severity:

```markdown
## Findings
- Critical: [...]
- Important: [...]
- Polish: [...]

## Verification
- [ ] Mobile checked
- [ ] Desktop checked
- [ ] Keyboard checked
- [ ] Console checked
```

## Completion Standard

A page is not ready for demo if the main CTA is unclear, the layout breaks on mobile, forms are untested, or accessibility basics are missing.
